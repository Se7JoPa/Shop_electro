# Магазин электроники


Настольное приложение: Python 3.11+, PySide6, PostgreSQL 16+.
Язык интерфейса: русский. Цены и товары в начальном каталоге демонстрационные.

## Что реализовано

- Вход по логину и паролю, регистрация покупателя.
- Роли: покупатель и администратор. Регистрация всегда создаёт покупателя.
- Каталог, карточка товара, описание и характеристики.
- Поиск по названию, фильтры категории, бренда, цены и наличия.
- Администратор добавляет, редактирует и удаляет товары с подтверждением.
- Выбор цвета кнопок и выделения. Цвет сохраняется в БД отдельно для каждого пользователя.
- Пароли хранятся как PBKDF2-SHA256 с солью; запросы используют параметры.

Фотографии, корзина, оплата и оформление заказов не входят в эту версию.
Это каталог для требований задания, а не работающий интернет-магазин.

## 1. Подготовка

Установите Python 3.11 или новее, PostgreSQL 16 или новее и Git.
В Windows при установке PostgreSQL запомните пароль пользователя postgres.
Распакуйте архив, откройте терминал в папке `electronics-shop`.

Windows PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

macOS / Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
```

Для Ubuntu: `sudo apt install python3-venv postgresql postgresql-contrib`.
У macOS и Windows приложение запускается локально, VPS не нужен.

## 2. Создание базы

В pgAdmin подключитесь как postgres. Откройте Query Tool и выполните
отдельно эти два запроса (CREATE DATABASE должен выполняться вне транзакции):

```sql
CREATE ROLE electronics_app LOGIN PASSWORD 'change_this_password';
```

```sql
CREATE DATABASE electronics_shop OWNER electronics_app;
```

Замените пример пароля своим. Затем зарегистрируйте в pgAdmin подключение
с пользователем `electronics_app`, вашим паролем и базой `electronics_shop`.
Откройте в этом подключении Query Tool, загрузите `schema.sql` и выполните.
Важно: таблицы нужно создавать именно от `electronics_app`, а не от postgres.
Скрипт предназначен для первого запуска в пустой базе; повторный запуск
ничего не удаляет и завершится ошибкой уже существующих таблиц.

Альтернатива для терминала, если psql доступен:

```bash
psql -h 127.0.0.1 -U electronics_app -d electronics_shop -f schema.sql
```

В `.env` укажите тот же пароль и настройки подключения. Не выкладывайте `.env` в Git.
База находится в PostgreSQL, а не в JSON или SQLite.

## 3. Первый администратор

Windows:

```powershell
.\.venv\Scripts\python.exe create_admin.py
.\.venv\Scripts\python.exe app.py
```

macOS / Linux:

```bash
.venv/bin/python create_admin.py
.venv/bin/python app.py
```

Создайте логин, например `shop_admin`, и свой пароль. При вводе пароля
в терминале символы не отображаются. Готового общего пароля нет.
Для покупателя нажмите «Регистрация покупателя» в окне входа.

## 4. Как показать преподавателю

1. Откройте `docs/ER_diagram.pdf`, объясните PK, FK и связи 1:N.
2. В pgAdmin покажите пять таблиц и ограничения.
3. Зарегистрируйте покупателя, выйдите, снова войдите.
4. Найдите `Samsung`, выберите категорию и диапазон цен, включите наличие.
5. Откройте карточку двойным щелчком. Сбросьте фильтры.
6. Измените цвет, выйдите и войдите: цвет должен сохраниться.
7. Войдите администратором, добавьте тестовый товар с характеристиками,
   отредактируйте цену и удалите товар с подтверждением.
8. Покажите `git log --oneline` и репозиторий на GitHub.

## 5. Git и публикация

В поставке есть настоящая локальная история Git: исходный код и дальнейшие
проверки. Если после распаковки `git log` не работает, ваша программа
распаковки могла пропустить скрытую папку `.git`. В таком случае:

```bash
git init
git add .
git commit -m "Initial electronics shop project"
```

Перед своими коммитами настройте автора:

```bash
git config user.name "ВАШЕ_ИМЯ_ИЛИ_НИК"
git config user.email "ВАША_ПОЧТА"
```

Создайте пустой репозиторий на GitHub, без README и .gitignore, затем:

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/electronics-shop.git
git switch postgresql
git push -u origin postgresql
```

Команды с ВАШ_ЛОГИН и ВАША_ПОЧТА нужно заменить своими значениями.
Последующие изменения:

```bash
git add .
git commit -m "Describe your change"
git push
```

Публикация на GitHub требует вашего аккаунта и не выполнена за вас.
Изучите код и добавляйте собственные доработки отдельными коммитами.

## 6. Структура

| Файл | Назначение |
|---|---|
| app.py | Окна входа, регистрации, каталога и редактора |
| db.py | Подключение к БД, запросы и проверка роли |
| security.py | Хеширование и проверка пароля |
| create_admin.py | Первоначальное создание администратора |
| schema.sql | Таблицы, внешние ключи, ограничения и учебные товары |
| docs/ER_diagram.pdf | Диаграмма сущность-связь |
| docs/REPORT_PLAN.md | План описания после демонстрации |
| tests/ | Проверки безопасности, БД и интерфейса |

## 7. Проверки

Базовые проверки паролей: `python -m unittest discover -s tests -p test_security.py`.
Интеграционные проверки выполняйте только на отдельной тестовой базе,
инициализированной `schema.sql`: они создают и удаляют тестовые записи.

```bash
python -m unittest discover -s tests -p test_integration.py
```

Перед этим задайте `DB_NAME=electronics_shop_test` переменной окружения
и остальные параметры подключения. Проверка откажется работать с именем
базы без окончания `_test`. Файл `.env` не перезаписывает переменные окружения.

## Ограничения

Приложение обращается к PostgreSQL напрямую. Роли защищают действия в
программе, но человек с паролем БД может обойти их прямым SQL-запросом.
Для реального магазина нужен сервер API, который скрывает доступ к БД.
Запросы выполняются в GUI-потоке: на медленной сети окно может временно
ожидать БД. Для локальной учебной демонстрации это допустимо.
Категории и бренды заведены в schema.sql; управление справочниками через
отдельное окно не реализовано. Их можно дополнять в pgAdmin.

Если появляется ошибка базы, проверьте сервис PostgreSQL, `.env`, порт 5432
и наличие таблиц. При занятом порте можно указать другой в `.env`.
