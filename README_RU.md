# Магазин электроники в браузере

Python 3.11+, Flask, SQLite, HTML и CSS.
Работает локально на Windows, macOS и Linux. Весь интерфейс на русском.

## Быстрый запуск

1. Установите Python 3.11 или новее с https://www.python.org/downloads/.
   В Windows отметьте Add Python to PATH.
2. Распакуйте архив в обычную папку, например «Документы».
3. Windows: откройте start_windows.bat. Mac: start_mac.command.
   При первом запуске установятся зависимости, поэтому нужен интернет.
4. Откроется браузер с адресом http://127.0.0.1:8000.
5. При первом запуске задайте имя, логин и пароль администратора.
   Затем войдите с этими данными. Готового общего пароля нет.

Терминал должен оставаться открытым. Для остановки нажмите Ctrl+C.
Если браузер не открылся автоматически, введите адрес вручную.

Если Mac не позволяет открыть .command, используйте терминал:
перейдите в папку проекта через cd, затем выполните команды ниже.
Не отключайте защиту macOS ради запуска файла.

## Ручной запуск

Откройте терминал в распакованной папке electronics-shop-web.

Windows PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

macOS / Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

Для Mac можно ввести cd с пробелом, перетащить папку проекта в терминал
и нажать Enter. Потом вводите команды по одной строке.
Повторный запуск: .venv/bin/python run.py (в Windows используйте путь выше).
SQLite входит в Python, отдельный сервер БД и PySide6 не нужны.

Если порт 8000 занят:

```bash
python run.py --port 8001
```

Команды с python выполняйте интерпретатором из .venv, как в примерах выше.
Флаг --no-browser отключает автоматическое открытие вкладки.
Это локальный сайт. Адрес 127.0.0.1 работает на том компьютере,
где запущена программа. С телефона или другого компьютера он не открывается.
Для публикации в интернете требуется отдельная настройка сервера и HTTPS.

## Что реализовано

- Первый запуск с созданием администратора.
- Вход, выход, регистрация покупателей и отдельные права администратора.
- Каталог с карточками товаров и страницами описания и характеристик.
- Поиск по названию, включая русский язык без учёта регистра.
- Фильтры категории, бренда, цены и наличия; сортировка по названию и цене.
  Выберите условия и нажмите «Найти» или «Применить фильтры».
- Добавление, редактирование и удаление товаров через браузер.
- Страница подтверждения удаления; характеристики удаляются с товаром.
- Сохранение своего цвета интерфейса в разделе «Оформление».
- Адаптивная вёрстка для узких экранов.

Изображения обозначают категории товаров, это иллюстрации, а не фотографии
конкретных моделей. Товары и цены демонстрационные. Корзины и оплаты нет.

## База и перенос из настольной версии

База автоматически создаётся в data/shop.sqlite3, рядом с файлами проекта.
Пять таблиц: users, categories, brands, products, product_specs.
SQL и схема сохранены: schema.sql и docs/ER_diagram.pdf.
Цена хранится целым числом копеек; в интерфейсе показаны рубли.

Для переноса существующих товаров и аккаунтов:

1. Закройте настольную программу и браузерный сервер.
2. Скопируйте старый data/shop.sqlite3 в data новой версии.
3. Если новая база уже создана, сначала сохраните её отдельную копию.
4. Запустите новую версию. Логины, пароли, цвета и товары сохранятся.

Структура SQLite совместима с предыдущей настольной версией. Автоматического
переноса данных из PostgreSQL нет. Новый запуск не восстанавливает удалённые
примеры. Для резервной копии закройте сервер и скопируйте файл базы.
Не удаляйте папку data, если хотите сохранить данные.

SQLITE_PATH может задать другой файл базы как переменная окружения.
Относительный путь считается от папки проекта. Файл .env не используется.
Ключ подписи входа создаётся в web_secret.key рядом с базой; он не входит в Git.

## Безопасность учебного проекта

Права проверяются сервером, пароли хранятся в виде PBKDF2-хешей с солью.
Изменяющие действия требуют POST и токен формы (CSRF).
Данные HTML экранируются; SQL использует параметры.
Сервер запускается только на 127.0.0.1, без отладчика.
Владелец файла SQLite может изменять его напрямую. Файл не зашифрован.
Не используйте личные пароли от других сервисов для учебных аккаунтов.

## Git и описание курсовой

Локальная история .git сохранена и дополнена коммитом браузерной версии.
Сначала настройте свои данные:

```bash
git config user.name "ВАШЕ_ИМЯ_ИЛИ_НИК"
git config user.email "ВАША_ПОЧТА"
git log --oneline
```

Создайте пустой репозиторий GitHub, замените ВАШ_ЛОГИН в адресе:

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/electronics-shop.git
git switch sqlite-web
git push -u origin sqlite-web
```

Для последующих изменений: git add ., git commit -m "Describe your change",
git push. База и ключи исключены из Git. На GitHub проект автоматически
не опубликован. План итогового документа: docs/REPORT_PLAN.md.
В исходном задании указаны MySQL/PostgreSQL: применение SQLite согласуйте
с преподавателем. Эта версия сохраняет выбранную вами SQLite.

## Проверки

Из папки проекта после установки зависимостей:

```bash
python -m unittest discover -s tests -v
```

Тесты создают временные базы и не меняют ваши данные.
Проверяются SQLite, пароли, HTTP-маршруты, права, формы, поиск, фильтры,
цвет, защита от CSRF и экранирование HTML. Результаты: docs/VALIDATION.md.

## Структура

- run.py: локальный сервер и открытие браузера.
- webapp.py: HTTP-маршруты, авторизация, права и формы.
- db.py: SQLite, транзакции, запросы.
- security.py: хеширование и проверка пароля.
- templates/: HTML-страницы.
- static/: стили и иллюстрации категорий.
- schema.sql: таблицы и учебные данные.
- tests/: проверки на временных БД.
